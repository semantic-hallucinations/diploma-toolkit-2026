# Visual Review Checklist

Дата формализации: 2026-05-19.

Минимальный чек-лист артефактов, которые нужно проверять на PNG после
генерации диаграммы. Если пункт воспроизводится, source-файл лучше сохранить
как regression example.

## Общие Проверки

- [ ] Открыт свежий PNG после последней генерации, а не старый файл.
- [ ] Текст не налезает на фигуры, линии, стрелки, рамки и другой текст.
- [ ] Текст помещается в фигуры и не обрезается.
- [ ] Подписи связей учитываются как отдельные элементы layout.
- [ ] Подпись связи стоит рядом со своей линией, но не лежит прямо на линии.
- [ ] Подпись связи не унесена слишком далеко от линии.
- [ ] Стрелки не проходят по контурам фигур, рамок и групп.
- [ ] Стрелки не идут слишком близко к фигурам, рамкам, цилиндрам БД и тексту.
- [ ] Стрелки не накладываются друг на друга и не превращаются в один общий
  пучок.
- [ ] Параллельные связи разведены на читаемое расстояние.
- [ ] Несколько связей не входят в одну и ту же точку без необходимости.
- [ ] Несколько связей не выходят из одной и той же точки без необходимости.
- [ ] Наконечник стрелки касается правильной стороны целевой фигуры.
- [ ] Наконечник стрелки не сливается с рамкой, границей группы или контуром
  фигуры.
- [ ] Связь не входит в фигуру параллельно ее грани, если из-за этого неясно,
  куда она подключена.
- [ ] Изломы линий не стоят вплотную к source/target фигурам.
- [ ] Длинные связи не обходят половину схемы без явной причины.
- [ ] Ортогональные маршруты не применены там, где диагональный участок
  заметно читабельнее.
- [ ] Нет лишнего пустого места, но между элементами достаточно воздуха.
- [ ] Фигуры не растянуты без необходимости.
- [ ] Границы групп не стоят вплотную к элементам и стрелкам.
- [ ] Layout не выглядит как случайная матрица, если связи требуют кластеров
  или слоев.
- [ ] Связи не проходят через unrelated элементы.
- [ ] Все стрелки имеют очевидные source и target.

## Sequence

- [ ] `loop`, `alt`, `else`, `opt` рамки не склеиваются границами.
- [ ] Вложенная рамка находится внутри родительской рамки.
- [ ] Нет лишнего пустого третьего блока внутри `alt/else`.
- [ ] Сообщения не пересекают текст заголовков fragment-рамок.
- [ ] Подписи сообщений не налезают на lifeline.
- [ ] Сообщения имеют достаточный вертикальный интервал.
- [ ] Lifeline выровнены и не конфликтуют с рамками fragments.
- [ ] Actor/system/database значки не деформированы.

## Class

- [ ] Наследование, реализация, композиция, агрегация, зависимость и ассоциация
  имеют правильные типы линий и markers.
- [ ] Связи не проходят вплотную к class box и не сливаются с его контуром.
- [ ] Близкие связи между двумя классами разведены.
- [ ] Связи не делают странный большой обход при доступном прямом маршруте.
- [ ] Граф расположен по смысловым слоям или кластерам, а не слепой сеткой.
- [ ] Поля и методы помещаются в compartments.
- [ ] Visibility markers `+`, `-`, `#`, `~` читаются и не заменены
  произвольной графикой.

## ERD

- [ ] Crow's foot/cardinality markers стоят точно на концах связей.
- [ ] Markers не плавают на линии и не отрываются от entity.
- [ ] Связи не проходят через таблицы.
- [ ] Связи между таблицами не накладываются друг на друга.
- [ ] Имена entity, поля, PK/FK и nullable признаки читаются.
- [ ] Форма entity простая и не мешает читать поля.

## C4

- [ ] У каждой связи понятны source и target.
- [ ] Нет стрелки, у которой непонятно, откуда она пришла и куда идет.
- [ ] Подписи связей не вынесены слишком высоко или далеко.
- [ ] Связи не идут вдоль system boundary или container boundary.
- [ ] Связи не входят в target параллельно его грани.
- [ ] Внешние акторы и системы не ломают layout внутренних контейнеров.
- [ ] Границы системы не пересекаются со стрелками и подписями.

## Deployment

- [ ] Иерархия environment/zone/node/pod/artifact читается сразу.
- [ ] Узлы, pods, очереди и БД не стоят вплотную к parent boundary.
- [ ] Стрелки не проходят по namespace/node boundary.
- [ ] Стрелки не проходят вплотную к цилиндрам БД.
- [ ] Стрелки не пересекают цилиндры БД и их верхние/нижние дуги.
- [ ] Cross-zone связи имеют отдельные lanes.
- [ ] В центре схемы нет каши из пересекающихся и наложенных стрелок.
- [ ] Вертикальное расстояние между horizontal lanes достаточное.
- [ ] Стрелки не входят в объект с неправильной стороны.
- [ ] Стрелки не выворачиваются коротким странным коленом у target.
- [ ] Внешние сервисы, storage и compute отделены визуально.
- [ ] Большие контейнеры не растянуты шире, чем нужно содержимому.

## Use Case

- [ ] Actor-to-use-case связи касаются периметра овала, а не его bounding box.
- [ ] Точки входа в овал разведены, если связей несколько.
- [ ] Actor links не перекрывают include/extend/generalization связи.
- [ ] Акторы стоят рядом со своими use cases без огромных пустых зон.
- [ ] Include/extend связи подписаны и не конфликтуют с основными связями.
- [ ] System boundary не пересекает актеров, овалы, стрелки и подписи.

## ML Pipeline

- [ ] Основной поток читается в одном направлении.
- [ ] Feedback/monitoring loop не пересекает основной поток в кашу.
- [ ] Decision branch labels вроде `yes/no` стоят рядом с нужной веткой.
- [ ] Шаги pipeline имеют стабильные размеры и интервалы.
- [ ] Стрелки касаются реального контура фигуры.
- [ ] Storage/dataset/model shapes не конфликтуют с process shapes.
