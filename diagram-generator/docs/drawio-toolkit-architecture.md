# Draw.io Toolkit Architecture

Дата формализации: 2026-04-26.

Цель инструментария - получать исходник диаграммы, строить нормализованную
модель, раскладывать элементы по правилам выбранного профиля, сохранять
редактируемый `.drawio` и экспортировать PNG для вставки в пояснительную
записку.

## Главный Принцип

Нельзя обещать `ГОСТ 19.701-90` для всех типов диаграмм.

Строгий ГОСТ-режим применим к схемам алгоритмов, программ, данных и систем.
Для `sequence`, `class`, `ERD`, `C4`, `deployment`, `ML pipeline` и `use case`
цель другая: строгий единый стиль пояснительной записки, прямые линии,
читаемый шрифт, черно-белая печатная форма, отсутствие визуального мусора и
предсказуемый PNG.

## Pipeline

```text
input
  -> source parser
  -> normalized diagram model
  -> semantic validator
  -> profile-specific layout
  -> obstacle-aware connector router
  -> draw.io mxGraphModel writer
  -> draw.io/png exporter
  -> visual and structural checks
```

## Входы

Поддерживать нужно только ограниченные и документированные subset-ы:

- Mermaid flowchart для ГОСТ-блок-схем;
- PlantUML activity для ГОСТ-блок-схем;
- Mermaid/PlantUML sequence;
- Mermaid/PlantUML class;
- Mermaid ERD и PlantUML IE/ER subset;
- Structurizr DSL или C4-PlantUML subset для C4;
- PlantUML deployment subset;
- YAML/JSON как основной внутренний и ручной формат;
- code extractors только как черновой источник, не как финальный renderer.

Если вход использует неподдерживаемую конструкцию, инструмент должен завершаться
понятной ошибкой, а не рисовать приблизительную схему.

## Нормализованная Модель

Все парсеры должны приводить вход к общей модели:

```text
diagram
  id
  title
  profile
  nodes[]
    id
    type
    label
    compartments[]
    stereotype
    metadata
  edges[]
    id
    source
    target
    type
    label
    direction
    metadata
  groups[]
    id
    type
    label
    children[]
```

Renderer draw.io не должен знать Mermaid/PlantUML напрямую. Он должен получать
уже нормализованную модель.

## Draw.io Output

Основной исходник - `.drawio`, потому что его можно открыть и поправить руками.
PNG - итоговый артефакт для LaTeX/записки.

Draw.io хранит элементы как `mxCell` внутри `mxGraphModel`. Значит, мы можем
генерировать:

- точные координаты `mxGeometry`;
- фиксированные размеры блоков;
- стили фигур;
- ортогональные соединители;
- подписи;
- группы и nested containers.

## Общий Стиль

Базовый стиль для всех профилей:

- фон белый;
- текст и линии черные;
- заливка белая;
- без теней, градиентов, sketch-эффектов и скругления, если нотация не требует
  обратного;
- один шрифт во всей диаграмме;
- минимальная высота строчных букв в итоговом размере - `2,5 мм`;
- единая толщина линий внутри диаграммы;
- соединители ортогональные, где это не ломает нотацию;
- подписи не выходят за границы фигур;
- диаграмма помещается в рекомендуемый размер рисунка для записки.

## Draw.io Фигуры

Для ГОСТ-блок-схем:

- использовать только разрешенные УГО;
- лучше иметь собственную библиотеку preset-ов, даже если часть фигур
  совпадает с draw.io flowchart shapes;
- фиксировать пропорции и правила соединения.

Для остальных профилей:

- использовать встроенные draw.io UML/ER/flowchart/network/container shapes
  только как техническую основу;
- стиль переопределять нашим профилем;
- не смешивать нотации внутри одной диаграммы;
- при сомнении рисовать простыми прямоугольниками/эллипсами с понятной
  семантикой, а не декоративными иконками.

## Экспорт PNG

Экспорт должен быть воспроизводимым:

- `.drawio` остается рядом с `.png`;
- PNG генерируется из `.drawio`, не из скриншота;
- фон белый или прозрачный по настройке профиля;
- без сетки canvas;
- с достаточным масштабом для печати;
- после экспорта проверяется размер, непустое изображение и базовая
  контрастность.

## Что Делать Первым

MVP:

1. `gost-flowchart` из Mermaid flowchart subset.
2. `.drawio` writer с фиксированными ГОСТ-фигурами.
3. PNG export.
4. Проверки: неподдерживаемые элементы, пересечения, текст за блоком,
   ортогональность линий, размер изображения.

После MVP:

1. `sequence`.
2. `class`.
3. `ERD`.
4. `C4`.
5. `deployment`.
6. `ML pipeline`.
7. `use case`.

## Статус Прототипа

Первый прототип diagram layer реализован в `src/diagram_toolkit`.

Он уже умеет генерировать `.drawio` и `.png` для:

- `sequence`;
- `class`;
- `ERD`;
- `C4`;
- `deployment`;
- `ML pipeline`;
- `use case`.

В прототипе уже выделены два технических слоя качества:

- `routing.py` - строит явные маршруты для связей без ручных точек, выбирает
  порты фигур и штрафует маршруты за пересечения, проход через фигуры,
  скученные точки входа/выхода и слишком короткие подписанные сегменты.
- `validation.py` - проверяет итоговый canvas на пересечения фигур, линии через
  чужие фигуры, наложение подписей, пустые маршруты и выход за границы холста.

Строгий flowchart layer для `ГОСТ 19.701-90` пока выделен как отдельная
следующая задача. Его нельзя смешивать с UML/C4/ERD renderer, потому что там
другой уровень формальности и другие правила проверки.
